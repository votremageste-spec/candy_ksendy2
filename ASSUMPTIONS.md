# Принятые решения и открытые вопросы

Живой документ. Редакция после перехода на **v3** — модель «заявка на
согласование» и бэкенд на Vercel.

Статусы: **[ПРИНЯТО]** — реализовано в коде · **[ОТКРЫТО]** — ждёт решения.

---

## 1. Архитектура v3

**[ПРИНЯТО] Бэкенд полностью на Vercel Serverless Functions.**
Противоречие прежних версий ТЗ (GCP Cloud Functions против Vercel) снято
в пользу Vercel. Firebase остаётся на бесплатном тарифе Spark: исходящие
вызовы к Telegram и Google идут из функции Vercel, а не из Cloud Functions,
для которых понадобился бы платный Blaze.

**[ПРИНЯТО] Регионы — Франкфурт.**
Функции в `fra1` (`vercel.json`), база Firestore в `europe-west3`.
Регион базы задаётся один раз при её создании и позже не меняется — проверьте
это до первого запуска.

**[ПРИНЯТО] Модель «заявка на согласование».**
Клиент не платит в приложении. Он отправляет заявку, Ксения связывается лично.
Формулировки везде приведены к этой модели: не «заказ оплачен», а «заявка
получена». Начальный статус — `⏳ На согласовании`.

**[ПРИНЯТО] Экраны, кроме стартового, грузятся отдельными кусками.**
Firebase SDK весит больше всего кода: без разделения главная тянула 692 КБ
вместо 197 КБ. Основной трафик — с телефонов по ссылке из профиля Instagram.

## 2. Безопасность

**[ПРИНЯТО] Клиент не пишет в базу вообще ничего.**
`firestore.rules`: коллекция `orders` закрыта и на чтение, и на запись.
Единственная точка записи — `/api/order` через Firebase Admin SDK.
Каталог (`components`, `categories`) открыт на чтение, пишет только админ.

**[ПРИНЯТО] Цену считает сервер.**
Клиент передаёт только идентификаторы выбранного и количество. `/api/order`
сам достаёт цены из Firestore, проверяет наличие, правила шагов и допустимое
количество, после чего считает сумму заново. Подменить итог через консоль
браузера невозможно. Реализация — `api/_lib/order-pricing.ts`.

**[ПРИНЯТО] Ловушка для ботов.**
Скрытое поле `biscuit_extra_accent`. Заполнено — сервер отвечает успехом
с выдуманным номером и не идёт в базу: бот считает рассылку удачной и не
подбирает обход.

**[ПРИНЯТО] Ограничение частоты — две заявки в минуту с адреса.**
Счётчики в Firestore, а не в памяти процесса: Vercel поднимает несколько
инстансов параллельно, и лимит «в памяти» обходился бы простым повтором.
IP хранится только в виде соли + хэша (`RATE_LIMIT_SALT`).

**[ПРИНЯТО] Подпись Telegram проверяется.**
`initDataUnsafe` подделывается в одну строку, поэтому на сервере
пересчитывается HMAC по алгоритму Telegram. Результат пишется в заявку полем
`isTelegramVerified` и виден Ксении в уведомлении галочкой.

**[ПРИНЯТО] Согласие по 152-ФЗ.**
Обязательный чекбокс на форме, факт и момент согласия сохраняются в заявке.
Страница `/privacy-policy` написана под самозанятую Епифанову К. С.

юридическим заключением: перед публикацией стоит показать его юристу.

⚠️ **[ПРИНЯТО ПОСЛЕ ИНЦИДЕНТА] Ключи лежали в `.env.example`.**
Все 16 реальных значений оказались в файле, который специально не внесён в
`.gitignore`, потому что существует как шаблон для репозитория. Плюс в корне
лежал `candy-ksendy-firebase-adminsdk-*.json` — сам файл закрытого ключа,
не подходивший ни под один шаблон исключений.

Что сделано: значения перенесены в `.env` (он игнорируется), `.env.example`
возвращён к пустому шаблону, правила `.gitignore` расширены и проверены на
временном репозитории. Git на момент обнаружения не был инициализирован,
наружу ничего не ушло.

Правило на будущее: **реальные значения только в `.env` и в переменных
окружения Vercel.** Файл `.env.example` — исключительно список имён.

**[ПРИНЯТО] Сбой Telegram или таблицы не теряет заявку.**
Запись в Firestore критична — не удалась, клиент видит ошибку. Уведомление
и строка в таблице вспомогательные: их сбой уходит в лог и записывается
в заявку полем `deliveryIssues`, чтобы Ксения увидела это в админке.

## 8. Что осталось по инфраструктуре

**[ПРИНЯТО] Все доступы выданы** и лежат в `.env` (не в репозитории).
Те же значения нужно продублировать в Vercel → Settings → Environment
Variables, иначе продакшен их не увидит. Ниже — откуда что берётся:

| Переменная | Где взять |
| :--- | :--- |
| `VITE_FIREBASE_*` | Консоль Firebase → Настройки проекта → Веб-приложение |
| `FIREBASE_PROJECT_ID` / `CLIENT_EMAIL` / `PRIVATE_KEY` | Firebase → Сервисные аккаунты → Создать ключ |
| `TELEGRAM_BOT_TOKEN` | @BotFather |
| `TELEGRAM_ADMIN_CHAT_ID` | @userinfobot в личке Ксении |
| `GOOGLE_SPREADSHEET_ID` | Из ссылки на таблицу |
| `GOOGLE_SERVICE_ACCOUNT_EMAIL` / `GOOGLE_PRIVATE_KEY` | См. `google-sheets-setup.md` |
| `RATE_LIMIT_SALT` | Любая случайная строка |

Полный список с пояснениями — в `.env.example`.

**[ПРИНЯТО] База Firestore создана.**
`(default)`, регион **`europe-west3` (Франкфурт)**, редакция STANDARD, тип
FIRESTORE_NATIVE. Регион задан командой, а не через консоль: в окне создания
выбор региона не применялся, оставаясь на `nam5`. Обход — открыть раздел
Firestore в консоли (это включает Cloud Firestore API), затем выполнить
`firebase firestore:databases:create "(default)" --location europe-west3`.

**[ПРИНЯТО] Защита от удаления базы включена** (`DELETE_PROTECTION_ENABLED`).
Удалить базу теперь нельзя ни командой, ни из консоли, пока флаг не снимут
осознанно. В отличие от региона настройка обратимая:
`firebase firestore:databases:update "(default)" --delete-protection DISABLED`.

**[ПРИНЯТО] Правила Firestore опубликованы и проверены.**
Опубликованный ruleset сверен с `firestore.rules` через Rules API —
совпадает побайтово. Дополнительно проверено поведение от лица анонимного
клиента, обычным веб-SDK:

| Действие | Результат |
| :--- | :--- |
| Чтение `components` (48 док.) | разрешено |
| Чтение `categories` (8 док.) | разрешено |
| Запись в `components` — подмена цены | запрещено |
| Чтение чужих заказов | запрещено |
| Создание заказа напрямую | запрещено |
| Чтение счётчиков антиспама | запрещено |

**[ПРИНЯТО] Каталог залит в базу.** 56 документов: 8 категорий и 48 позиций.
Сезонные категории выключены, позиций без подтверждённой цены нет.
Повторный запуск `npm run seed` существующие документы не трогает — правки
Ксении в админке не затираются. Для перезаписи есть флаг `--force`.

**[ПРИНЯТО] Счётчики антиспама убирает сам код, а не TTL.**

⚠️ **Правило TTL в Firestore требует включённого биллинга** — на бесплатном
плане Spark оно недоступно. Консоль отвечает прямым текстом:
`403: Project candy-ksendy has billing disabled`. Это выяснилось не сразу:
сначала мешало отсутствие прав у сервисного аккаунта, потом отсутствие самой
коллекции в списке, и лишь затем всплыла настоящая причина.

Поскольку переход на Blaze противоречит решению остаться на бесплатном плане,
уборка перенесена в код. В `api/_lib/rate-limit.ts` появилась `sweepExpired`:
изредка — с вероятностью 5 % на вызов — она удаляет до 25 просроченных
счётчиков запросом `where('expiresAt', '<', now)`.

Почему этого достаточно: счётчик становится ненужным через десять минут после
попытки, а заявок у домашнего кондитера единицы в день. Запрос обходится
автоматическим одиночным индексом, отдельный создавать не нужно — проверено
на живой базе. Ошибки уборки поглощаются: она не должна ронять оформление
заказа.

Поле по-прежнему называется `expiresAt`. Если проект когда-нибудь переедет на
Blaze, хватит включить TTL в консоли — код менять не придётся.

Запасной вариант, если объёмы вырастут: ежедневный Vercel Cron, дёргающий
отдельный эндпоинт уборки. На бесплатном плане Vercel это доступно.

| Почта | UID |
| :--- | :--- |
| `klavdija0008@gmail.com` | `i0gF0VYwS3Sh6SxF1A28PzqrYyU2` |
| `votre.mageste@gmail.com` | `Fs1Up2RxRgdJaGwmfaDouVvjTM22` |

Обе записи созданы заранее скриптом `npm run grant-admin`: правила требуют
документ `users/{uid}`, а UID появляется только после первого входа —
замкнутый круг. Круг разорван тем, что настройка «один аккаунт на адрес почты»
включена (`allowDuplicateEmails: false`): вход через Google свяжется с уже
созданной записью, и UID не изменится. **Отключать эту настройку нельзя** —
права слетят.

Проверено выпуском настоящих токенов: оба администратора проходят,
посторонний получает 403, подделанный токен отклоняется.

**[ПРИНЯТО] Authentication включается только из консоли.**
Через API не вышло: инициализация возвращает `BILLING_NOT_ENABLED`, потому что
API управляет платным Identity Platform. Обычный Firebase Authentication
бесплатен и включается в консоли — тот же случай, что и с TTL.

**[ПРИНЯТО] Заявки читаются только через сервер.**
Коллекция `orders` закрыта правилами и на чтение тоже, поэтому журнал ходит
в `/api/orders`, а смена статуса — в `/api/order-status`. Проверка прав в два
шага: подпись токена Firebase плюс роль в базе. Одной подписи мало — она
подтверждает, что человек вошёл, а не что он Ксения.

Каталог, наоборот, правится напрямую в Firestore: правила это администратору
разрешают, а конструктор у клиентов подписан на базу через `onSnapshot` —
тумблер наличия срабатывает у всех сразу, без перезагрузки.

**[ПРИНЯТО] Статус в таблице ищется по номеру заявки, а не по номеру строки.**
`updateOrderStatusInSheet` читает столбец A, находит заявку и пишет в столбец M.
Так синхронизация переживает ручную сортировку и вставку строк: Ксения работает
с таблицей как с таблицей, а не как с базой данных.

**[ПРИНЯТО] Добавлен статус «Отменена».**
Заявка, от которой клиент отказался, не «выдана» и не должна теряться среди
новых. Значение добавлено в `OrderStatus`, подписи — в `ORDER_STATUS_LABELS`
и `SHEET_STATUS_LABELS`.

⚠️ **[ОТКРЫТО] Домен Vercel не внесён в разрешённые для входа.**
Сейчас в списке только `localhost`, `candy-ksendy.firebaseapp.com` и
`candy-ksendy.web.app`. После деплоя вход через Google на боевом домене упадёт
с ошибкой `auth/unauthorized-domain`. Добавить домен: консоль Firebase →
Authentication → Settings → Authorized domains.

**[ПРИНЯТО] Владелец аккаунтов.** На время разработки — вы, по завершении
проект передаётся Ксении. При передаче нужно сменить владельца проектов
Firebase и Google Cloud, перевыпустить ключи сервисных аккаунтов и передать
бота в BotFather.

**[ПРИНЯТО] Домен и аналитика.** Домен пока технический, от Vercel; свой
Ксения выберет позже. Аналитика — Яндекс Метрика, счётчик пока не подключён.

**[ПРИНЯТО] Вес куска конструктора оставляем как есть.** 121 КБ в сжатом
виде, почти всё — Firestore. Если понадобится ускорять, вариант известен:
отдавать каталог обычным JSON с серверной функции.

⚠️ Кусок конструктора весит 121 КБ в сжатом виде, почти всё это Firestore.
Если понадобится ускорять дальше — отдавать каталог обычным JSON с серверной
функции вместо прямого чтения базы из браузера.

## 9. Ответ на вопрос о постер-кадрах

Постер — это картинка, которую браузер показывает **до того, как видео
начало играть**. Нужны два, оба извлекаются из уже готовых роликов, снимать
ничего не надо:

1. **Постер фонового видео** — любой удачный кадр из `4236-1.mp4`.
   Горизонтальный, примерно 1280×720. Сейчас вместо него подставлена
   случайная фотография из папки, и в момент загрузки страницы видно, как
   одна картинка сменяется другой.

2. **Обложка видео «О себе»** — кадр из `5589-1 о себе.mp4`, вертикальный,
   примерно 720×1280. Сейчас используется фотография Ксении с тортом; она
   хорошо смотрится, так что этот постер желателен, но не обязателен.

Оба кадра извлекаются одной командой ffmpeg, если он у вас установлен:

```
ffmpeg -i "4236-1.mp4" -ss 00:00:02 -vframes 1 ksenia-baking-poster.jpg
ffmpeg -i "5589-1 о себе.mp4" -ss 00:00:01 -vframes 1 ksenia-about-poster.jpg
```

Либо просто поставьте видео на паузу на нужном кадре и сделайте снимок экрана.

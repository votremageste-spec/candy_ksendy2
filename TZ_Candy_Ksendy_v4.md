# Техническое задание (ТЗ): Candy_Ksendy — Конструктор десертов — Версия 4

Данный документ является главным инженерным и архитектурным руководством для сборки веб-приложения и Telegram Mini App кондитерской «Candy_Ksendy» (г. Химки). Архитектура построена на принципах **Vibe-coding** с использованием единой кодовой базы (Single Codebase), высокой производительности и нулевой стоимости обслуживания инфраструктуры на малых и средних масштабах.

---

## 1. Концепция продукта и его ценность (App Value)
Конструктор десертов Candy_Ksendy решает ключевую боль домашнего кондитера Ксении — рутину ручного приема, калькуляции и согласования индивидуальных заказов через мессенджеры. 
Приложение предоставляет клиенту удобный, визуально безупречный шаг-за-шагом конструктор для моделирования десертов под свои вкусы и бюджет. При этом заказ формируется не как мгновенная покупка, а как **Заявка на согласование (Order Request)**, так как кондитерское производство премиум-класса требует подтверждения свободных дат, наличия свежих ингредиентов и внесения предоплаты вручную.

---

## 2. Технологический стек и архитектура «Цифрового Ресторана»
Приложение использует гибридную бессерверную архитектуру (Serverless Frontend + Backend) с бесплатным размещением на Vercel и базой данных на Firebase.

*   **Фронтенд (Клиентский зал):** React (TypeScript) + Tailwind CSS + Lucide Icons. Проект собирается с помощью сверхбыстрого сборщика Vite. Отсутствуют тяжелые сторонние стейт-менеджеры (используется чистый Context API).
*   **Бэкенд (Кухня):** Vercel Serverless Functions (Node.js / TypeScript). Все серверные функции располагаются в корневой директории `/api` и работают абсолютно бесплатно, не блокируя внешние сетевые запросы.
*   **База данных (Кладовка):** Firebase Cloud Firestore (тариф Spark, полностью бесплатный лимит). Хранит структуру ингредиентов и лог заказов.
*   **Хранилище медиа (Морозильник):** Firebase Storage. Используется для хранения тяжелых изображений ингредиентов и фонового презентационного видео Ксении.
*   **Интеграции (Официанты):** 
    *   **Telegram Bot API** — для отправки моментальных красивых HTML-уведомлений о заявках.
    *   **Google Sheets API** — для автоматического ведения учёта заказов в Google Таблице Ксении через Service Account.
    *   **Telegram WebApp API** (`window.Telegram.WebApp`) — для тактильного Haptic-отклика на устройствах пользователей и бесшовного извлечения ников.

## 3. Архитектура базы данных Firestore
Для обеспечения гибкости ассортимента и мгновенного изменения цен со смартфона без изменения кода, структура конструктора полностью управляется данными в Firestore.

### 3.1. Коллекция `components` (Ингредиенты и опции)
Каждый документ в коллекции описывает отдельную опцию выбора в конструкторе:
```typescript
interface DBComponent {
  id: string;          // уникальный ID (например, "biscuit-chocolate")
  category: string;    // категория десерта ("tortes", "bento", "moti", etc.)
  step: string;        // к какому шагу относится ("step1_flavor", "step2_decor", etc.)
  name: string;        // название на русском (например, "Чёрный лес")
  price: number;       // наценка/стоимость за единицу (рубли)
  inStock: boolean;    // тумблер наличия (если false, скрывается в интерфейсе)
  imageUrl?: string;   // ссылка на фото в Cloud Storage
}
```

### 3.2. Коллекция `orders` (Заказы)
Каждый документ фиксирует отправленную заявку клиента:
```typescript
interface DBOrder {
  id: string;             // автогенерируемый ID Firestore
  createdAt: string;      // дата и время создания (ISO)
  client: {
    name: string;
    phone: string;
    telegram?: string;    // подставляется автоматически из Telegram WebApp
  };
  items: Array<{
    category: string;
    name: string;         // название категории десерта
    quantity: number;     // вес в кг или количество штук/наборов
    details: string;      // текстовое описание состава (бисквиты, начинки, декор)
    componentIds: string[]; // массив ID выбранных компонентов для пересчёта цен
  }>;
  total: number;          // итоговая стоимость, строго рассчитанная СЕРВЕРОМ
  pickupTime: string;     // желаемая дата и время самовывоза (не ранее 48 часов)
  wishes?: string;        // особые пожелания к декору
  status: 'pending' | 'confirmed' | 'completed' | 'cancelled'; // статус заявки
  deliveryIssues?: string; // фиксация ошибок отправки в Telegram или Google Sheets
}
```

## 4. Спецификация Конструктора (Реальный Ассортимент Ксении)
В отличие от абстрактных шаблонов, конструктор работает на реальной продуктовой матрице Ксении. Правила выбора шагов задаются динамически метаданными (минимум и максимум выбранных элементов), а не жестко зашиты в коде.

| Категория | Шаг 1 (Начинка / Вкус) | Шаг 2 (Оформление / Тесто / Обсыпка) | Вес / Количество | Базовая цена |
| :--- | :--- | :--- | :--- | :--- |
| **Торты** | *Начинка:* Шоколадный трюфель, Чёрный лес | *Декор:* Базовое оформление (0 ₽), Ягодный (+500 ₽), Надпись (+200 ₽), Сложный (+1000 ₽) | От 1.5 до 5 кг (шаг 0.5 кг) | 2500 ₽ / кг |
| **Бенто-торты** | *Начинка:* Шоколад-вишня, Шоколад-карамель, Ваниль-клубника, Ваниль-вишня, Ваниль-тропик, Ягодный пломбир | *Декор:* Простой (входит, 0 ₽), Сложный (+300 ₽) | Фиксировано: 1 шт (~450-500 г) | 1500 ₽ / шт |
| **Моти** | *Вкус:* Эрл грей-клубника, Бабл гам, Манго-маракуйя, Ферреро, Тирамису, Дубайский, Груша-горгонзола, Личи-малина | *Тесто:* Классическое, Шоколадное, Кофейное, Фруктовое | Набор от 4 до 12 шт | 170 ₽ / шт |
| **Птичье молоко** | Набор конфет Птичье молоко (9 шт) | *Обсыпка:* **Ровно 3 из 4** (Клубника, Какао, Кокос, Фисташка) | Набор от 1 до 5 коробок | 550 ₽ / набор |
| **Мадлен** | Набор пирожных Мадлен (9 шт) | *Вкусы:* **От 1 до 2 вариантов** (Шоколадный, Ванильный) | Набор от 1 до 5 коробок | 1000 ₽ / набор |
| **Зефир** | Набор домашнего зефира (6 шт) | *Вкусы:* **От 1 до 2 вариантов** (Чёрная смородина, Клубника) | Набор от 1 до 5 коробок | 700 ₽ / набор |
| **Куличи** *(Сезон)* | *Тип кулича:* Классический (750 ₽), Морковный (800 ₽), Царский (950 ₽), Дубайский (1300 ₽), Краффин (900 ₽), Кексовый шоколадный (850 ₽), Творожный (900 ₽) | — | От 1 до 10 шт | Зависит от кулича |
| **Творожные пасхи** *(Сезон)* | *Вкус:* Фисташковая (1800 ₽), Карамельно-ореховая (1700 ₽), Ванильная (1600 ₽), Шоколадная (1650 ₽) | — | От 1 до 5 шт | Зависит от вкуса |

### 4.1. Универсальная формула расчёта цены
Стоимость десерта всегда рассчитывается строго по формуле:
$$\text{Цена} = (\text{Цена за единицу} \times \text{Количество/Вес}) + \text{Стоимость доплат за декор/доп. опции}$$
Цену несёт выбранная начинка, вкус или базовый тип изделия, а не сумма мелких ингредиентов. Единица измерения варьируется: килограмм (для тортов), штука (для бенто и куличей) или коробка/набор.

## 5. Безопасность и Валидация (Crash Early)

1.  **Защита базы данных (Firestore Rules):** Клиентскому приложению из браузера полностью закрыт доступ на прямую запись в коллекцию `orders`. Все заказы создаются только через серверную функцию Vercel (`/api/order.ts`) с использованием Firebase Admin SDK. База защищена от несанкционированного изменения цен и чтения чужих данных.
2.  **Серверный пересчёт цен:** Фронтенд передаёт на сервер только ID выбранных компонентов и количество. Бэкенд-функция самостоятельно делает запрос к Firestore, извлекает проверенные цены Ксении из БД, пересчитывает сумму и записывает её в финальный чек. Попытки подменить цену на клиенте блокируются.
3.  **Антиспам-фильтрация (Honeypot + Rate Limit):** 
    *   **Honeypot:** В форму чекаута встроено скрытое поле. Если бот заполняет его, сервер тихо сбрасывает запрос.
    *   **Rate Limit:** IP-адреса хэшируются с солью и сохраняются в Firestore в коллекции `rate_limits`. Лимит — максимум 2 отправки заказов с одного IP в минуту. Очистка старых лимитов происходит автоматически с помощью включенного в консоли Firebase правила TTL по полю `expiresAt`.
4.  **Регионы выполнения:** Для минимизации задержек Firestore развернута в регионе `europe-west3` (Франкфурт), а бессерверные функции Vercel настроены на регион `fra1` (Франкфурт).
5.  **Data Privacy (152-ФЗ):** Рядом с кнопкой отправки заказа расположен обязательный чекбокс согласия на обработку персональных данных со ссылкой на статическую страницу `/privacy-policy`.

## 6. Этапы разработки (Staging Roadmap)

*   **STAGE 1:** Базовая инфраструктура, шаблоны конфигураций, адаптивный Хедер и Welcome-экран с личной историей Ксении и сжатым фоновым видео-презентацией.
*   **STAGE 2:** Развертывание Firestore базы данных, заполнение коллекции `components` реальным ассортиментом Ксении.
*   **STAGE 3:** Сборка пошагового конструктора на React Context с динамической загрузкой опций и 24 авто-тестами валидации правил выбора.
*   **STAGE 4:** Верстка модального окна Checkout (Drawer), интеграция маски телефона, Honeypot, чекбокса 152-ФЗ и анимации отправки.
*   **STAGE 5:** Создание бэкенда на Vercel Serverless Functions (`/api/order.ts`), подключение Firebase Admin SDK и логики серверного расчёта цен.
*   **STAGE 6:** Настройка интеграции бэкенда с Telegram Bot API (проверка подписи HMAC) и Google Sheets API через Сервисный аккаунт.
*   **STAGE 7:** Разработка защищенного паролем роута `/admin` для быстрого переключения Ксенией доступности ингредиентов и ведения журнала заявок.

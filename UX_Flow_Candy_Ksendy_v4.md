# Сценарии переходов и логика экранов (UX & Flow): Candy_Ksendy — Версия 4

Этот документ описывает полную информационную архитектуру, пользовательские сценарии, правила валидации данных, логику интеграции внешних сервисов и обработку ошибок в приложении Candy_Ksendy. Документ служит строгим техническим регламентом обслуживания гостей цифровой кондитерской Ксении.

---

## 1. Глобальная архитектура экранов и переходов
Путь клиента спроектирован по принципу линейного туннеля с минимальным числом кликов до конверсии (подачи заявки):

```text
[Экран 1: Welcome / О Ксении] 
       │ (Клик на «Собрать свой шедевр» с тактильным откликом)
       ▼
[Экран 2: Конструктор (Workspace)] ──► [Админ-панель (/admin)] (Скрытый роут)
       │ (Сборка десерта по табам в реальном времени)
       ▼
[Экран 3: Оформление (Checkout Drawer)] 
       │ (Заполнение формы, маска телефона, проверка ловушки Honeypot)
       ▼
[Экран 4: Экран успеха (Success Screen)]
```

## 2. Подробное описание сценариев по экранам

### Экран 1: Welcome / О Ксении (Стартовый видео-лендинг)
*   **UI-интерфейс:**
    *   **Фоновое видео:** На заднем плане зацикленно и беззвучно проигрывается аппетитное, эстетичное видео процесса сборки или декорирования десертов Ксенией (сжатый файл `IMG_4236.MP4`, оптимизированный с 22.7 МБ до 987 КБ для мгновенной загрузки на мобильном интернете).
    *   **Матовая карточка бренда:** Поверх видео располагается нежная полупрозрачная карточка цвета шампани с логотипом Candy_Ksendy и личной фотографией Ксении.
    *   **Текст личного бренда:** *«Каждый десерт — это холст, а ингредиенты — мои краски. Создаю сладкие шедевры вручную в Химках для ваших особенных моментов. — Ксения»*.
    *   **Кнопка действия (CTA):** Крупная ягодная кнопка **«Собрать свой шедевр»**.
*   **UX-логика:**
    *   Клиент сразу проникается доверием к личности автора и понимает премиальную ценность ручной работы.
    *   При клике на CTA-кнопку срабатывает вибрация `medium` на смартфоне через Telegram WebApp API, фоновое видео плавно затухает, и интерфейс переходит к экрану Конструктора.

### Экран 2: Интерактивный Lego-Конструктор (Workspace)
*   **UI-интерфейс:**
    *   **Выбор категории:** Вверху экрана расположены горизонтальные переключатели категорий (Торты, Бенто, Моти, Птичье молоко, Мадлен, Зефир, Сезонные предложения).
    *   **Пошаговые табы:** Под категорией отображается прогресс-бар шагов (например, для тортов: *«Шаг 1: Выберите начинку» ➔ «Шаг 2: Выберите декор» ➔ «Шаг 3: Выберите вес»*).
    *   **Визуальный результат:** На десктопе справа всегда отображается большой интерактивный макет десерта. При выборе начинки «Чёрный лес» на макете торта появляются сочные ягоды вишни, при выборе шоколадной обсыпки для птичьего молока — коробка визуально покрывается какао-пудрой.
    *   **Калькулятор стоимости:** Внизу закреплена панель с итоговой стоимостью, которая пересчитывается на лету по формуле: *базовая цена начинки × количество + доплаты за декор*.
*   **UX-логика:**
    *   Пользователь не может перейти к следующему шагу, пока не выполнит правила текущего шага (например, в категории «Птичье молоко» нужно выбрать **ровно 3 из 4** вариантов обсыпки, а в «Мадлен» — **от 1 до 2** вкусов). Нарушение правил подсвечивается мягкой подсказкой, а кнопка «Далее» блокируется.
    *   В случае, если Ксения отключила какую-то начинку в админке, карточка ингредиента переходит в состояние *Out of Stock* (тускнеет, блокируется для кликов и получает бейдж *«Закончился»*).

### Экран 3: Модальное окно Checkout (Drawer)
При клике на кнопку «Оформить заявку» снизу плавно выезжает панель (Drawer).
*   **Поля ввода:**
    *   **Имя:** Текстовое поле, обязательное.
    *   **Телефон:** Поле ввода с маской телефона РФ (`+7 (999) 999-99-99`), обязательное.
    *   **Telegram:** Никнейм. Если приложение открыто внутри Telegram Mini App, система автоматически подставляет ник пользователя (например, `@username`) из `window.Telegram.WebApp.initDataUnsafe.user.username` и блокирует поле для редактирования (для защиты от опечаток).
    *   **Дата и время самовывоза:** Выбор даты с помощью календаря. Валидация: **не ранее, чем через 48 часов** от текущего момента (так как Ксении требуется минимум 2 дня на подготовку премиального сырья и выпечку).
    *   **Пожелания к заказу:** Многострочное текстовое поле для деталей декора, надписей или уточнений.
    *   **Honeypot (Защита от спама):** Невидимое для человека поле ввода `biscuit_extra_accent`. Спам-боты заполнят его автоматически, и сервер тихо отклонит их заявку.
    *   **Согласие 152-ФЗ:** Обязательный чекбокс: *«Я соглашаюсь на обработку персональных данных»* со ссылкой на `/privacy-policy`.
*   **UX-логика:**
    *   При клике на кнопку отправки кнопка переходит в состояние загрузки: *«Превращаем ингредиенты в искусство...»*.
    *   Запускается тактильный отклик смартфона. Фронтенд собирает ID выбранных компонентов и отправляет их методом `POST` на защищенный эндпоинт `/api/order`.

*   **UI-интерфейс:**

    *   **Тёплый текст успеха:**

Она проверит календарь выпечки и свяжется с вами в течение часа, чтобы подтвердить свободную дату, обсудить индивидуальный декор и договориться о предоплате (стандартная предоплата составляет 50%).     *   Крупная кнопка возврата на главную страницу или перехода обратно в чат Telegram-бота Ксении.

## 3. Логика серверных интеграций (Бэкенд-маршруты)

Когда серверная функция `/api/order.ts` получает запрос, она выполняет следующие шаги по порядку:

1.  **Проверка ловушки Honeypot:** Если скрытое поле заполнено, функция возвращает статус `200 OK`, но прекращает выполнение (имитация успеха для спам-ботов).
2.  **Проверка лимита частоты (Rate Limit):** Хэширует IP-адрес пользователя с солью и делает запрос в Firestore в коллекцию `rate_limits`. Если лимит превышен (более 2 запросов в минуту), возвращает ошибку `429 Too Many Requests`.
3.  **Проверка подписи Telegram (HMAC):** Пересчитывает контрольный хэш входящих данных сессии, сверяя их с секретным токеном бота. При успешной проверке Ксения получит в Telegram уведомление со специальной отметкой (галочкой) «Личность клиента подтверждена через Telegram».
4.  **Расчёт стоимости:** Функция извлекает актуальные цены ингредиентов Ксении из Firestore, пересчитывает общую сумму и сохраняет документ в коллекцию `orders` со статусом `pending`.
5.  **Запись в Google Таблицу:** Дописывает строчку в конец «Лист1» через сервисный аккаунт Google Cloud. Колонки включают: ID заказа, дату создания, имя клиента, телефон, Telegram, состав десерта (бисквиты, начинки, декор по шагам) и сумму. Если Google API временно недоступен, заказ всё равно создаётся, а ошибка пишется в поле `deliveryIssues` документа Firestore.
6.  **Уведомление в Telegram:** Отправляет Ксении детальное HTML-сообщение о новой заявке. Сообщение содержит кликабельную ссылку на созданную Google Таблицу для удобного ведения учета.

## 4. Сценарий Администратора (/admin)
*   **Доступ:** Скрытая страница по адресу `/admin`. При переходе проверяется роль пользователя в Firestore (`user.role === 'admin'`). Обычные пользователи автоматически перенаправляются на главную.
*   **Экран «Управление ингредиентами»:**
    *   Ксения видит простую таблицу всех компонентов с поиском и фильтрацией по категориям десертов.
    *   У каждого ингредиента есть **тумблер наличия (In Stock)** и текстовое поле для быстрого редактирования цены.
    *   При изменении тумблера или цены данные мгновенно обновляются в Firestore и на лету применяются у всех клиентов, находящихся в этот момент в конструкторе (благодаря real-time подписке Firestore `onSnapshot`).
*   **Экран «Журнал заявок»:**
    *   Список всех заявок от клиентов с сортировкой по дате самовывоза.
    *   Возможность раскрыть каждую заявку и посмотреть полный рецепт десерта, собранного клиентом.
    *   Выпадающий список для ручного изменения статуса заявки: *На согласовании (pending) ➔ Подтвержден (confirmed) ➔ Выдан (completed) ➔ Отменен (cancelled)*. Изменение статуса автоматически подсвечивает строчку в Google Таблице Ксении соответствующим цветом.
